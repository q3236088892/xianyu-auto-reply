## 4. 本次搭建遇到的坑（重要！迁移或重装时可能重现）

### 坑 A：`.env` 加载路径不匹配

**症状**：backend-web 启动时报 `Unknown database 'xianyu_data'`，但 `backend-web/.env` 里明明写的是 `xianyu_auto_reply`。

**根因**：`scripts/run_release.py` 会 `os.chdir(app_root)`，pydantic 的 `env_file=".env"` 是相对 cwd 找的，所以它找的是**项目根目录**的 `.env`，找不到就退回代码里的默认值 `xianyu_data`。

**修复**：在项目根目录 `.env` 放一份和 `backend-web/.env` 相同的连接信息。三个服务共用无冲突（服务端口通过 launcher 注入的环境变量覆盖）。

**根 `.env` 参考内容**：

```dotenv
ENVIRONMENT=production
LOG_LEVEL=INFO
HOST=127.0.0.1
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=root
MYSQL_DATABASE=xianyu_auto_reply
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=
REDIS_DB=0
BACKEND_WEB_PORT=8089
CORS_ORIGINS=*
AUTO_START_CRAWL_JOBS=true
WEBSOCKET_SERVICE_URL=http://127.0.0.1:8090
SCHEDULER_SERVICE_URL=http://127.0.0.1:8091
STATIC_DIR=C:\business\xianyu-auto-reply-portable\backend-web\static
BACKUP_DIR=C:\business\xianyu-auto-reply-portable\backups
FRONTEND_PUBLIC_URL=http://127.0.0.1:9000
BACKEND_WEB_PUBLIC_URL=http://127.0.0.1:8089
```

⚠️ 迁移到新机器后如果这份 `.env` 没跟着复制，backend-web 一定会连库失败。

### 坑 B：三个服务的启动竞态导致 websocket 挂

**症状**：backend-web 已经 running，但 websocket 立即报 `Table 'xianyu_auto_reply.xy_risk_control_logs' doesn't exist`。

**根因**：launcher 并行启动三个服务，backend-web 的 `init_database`（建 50+ 张表）是异步任务，比 websocket 的启动检查慢，导致 websocket 早于建表完成就去查表。

**修复（一次性）**：手动跑一次建表：

```bash
runtime/python/python.exe scripts/run_release.py . state/deps/<active-commit> --module common.db.init_database
```

`<active-commit>` 可从 `state/active-release.json` 取。建表是幂等的（`CREATE TABLE IF NOT EXISTS`），后续启动 backend-web 会自动跳过已存在的表。

一次建完后，之后 `STOP.cmd` → `START.cmd` 循环不会再触发这个问题（表已经存在，websocket 不会报错）。

### 坑 C：局域网访问不通（9000）

**根因**：`scripts/portable_manager.py` 里 `_serve_frontend` 和 `serve_frontend_command` 两处把 host 硬编码成了 `127.0.0.1`。

**已修复**：改成 `0.0.0.0`，同时增加了 Windows 防火墙规则。

如果迁移后仍无法从局域网访问，检查：

```powershell
# 查看规则
netsh advfirewall firewall show rule name="XianyuAutoReply Frontend 9000"

# 添加规则（如未加）
netsh advfirewall firewall add rule name="XianyuAutoReply Frontend 9000" dir=in action=allow protocol=TCP localport=9000
```

后端 3 个端口保持 `127.0.0.1` 不动，这是刻意为之的安全默认。

### 坑 D：STOP 会连带停 MySQL/Redis

`STOP.cmd` 走的是 `portable_manager stop`，它会同时停止 `state/deps-process.json` 里记录的 MySQL/Redis。这是设计如此，不是 bug。如果只想重启应用而不重启数据库：

```bash
runtime/python/python.exe -c "import sys; sys.path.insert(0,'scripts'); from portable_manager import stop_services; stop_services('.')"
```

不过一般直接跑 `STOP.cmd` + `START.cmd` 即可，launcher 会自动把 MySQL/Redis 拉回来。

## 6. 更新与回滚（保留最早版本能力）

绿色版通过 `UPDATE.cmd` 从上游 Git 一键更新。流程：

1. 查询 `origin/main` 最新提交
2. 隔离下载源码到 `staging/`
3. 独立安装 Python 依赖到 `state/deps/<new-commit>/`
4. `compileall` 全量编译（缓存到 `__pycache__/`）
5. 运行上游 unittest
6. 启动 Playwright Chromium 冒烟
7. 用候选端口 `18089/18090/18091/19000` 起一份新版做健康检查
8. 备份当前生产 → 停止 → 切换 → 在正式端口再次校验
9. 切换后如果健康失败，自动恢复旧版

失败可查 `logs/maintenance/*.jsonl`。手工回滚：

```bat
ROLLBACK.cmd
```

依赖 `state/last-update.json`；首次安装没有上一版本时会拒绝。

**编译一次的方法**（不走完整更新）：

```bat
VERIFY.cmd
```

`VERIFY.cmd` 会跑 compileall；输出里 `"compileall": "ok"` 即成功。

## 7. 迁移到另一台电脑

严格按照 `docs/03-迁移到另一台电脑.md` 走：

1. 原电脑：`REMOVE-TASK.cmd`（移除计划任务）→ `STOP.cmd`
2. 完整复制整个 `xianyu-auto-reply-portable/` 目录（**包括 `.env`、`state/`、`backups/`**，不要只复制源码）
3. 新电脑上到目标路径，依次跑：`VERIFY.cmd`、`START.cmd`、`STATUS.cmd`
4. 打开 `http://127.0.0.1:9000` 验证
5. `INSTALL-TASK.cmd` 重建每日自动更新计划任务（含新绝对路径）

**关键：**

- `state/mysql-data/` 必须一起复制，否则数据丢失
- 目标机器不需要预装 Python/Node/Git/MySQL/Redis，`runtime/` 里都带了
- 路径可以含空格，`portable_manager.py` 从自身位置推导根目录，不依赖 cwd
- 迁移后如果 9000 局域网访问不通，去新机器上照坑 C 加防火墙规则

## 8. 日常运维速查

### 8.1 查看服务状态

```bat
STATUS.cmd
```

返回 JSON，`services.<name>.running=true` 表示运行中。

### 8.2 查看某个服务的日志

```bash
tail -f logs/app/backend-web.log
tail -f logs/app/websocket.log
tail -f logs/app/scheduler.log
tail -f logs/app/frontend.log
tail -f logs/deps/mysql/mysql.log
tail -f logs/deps/redis/redis.log
```

### 8.3 端口冲突排查

```powershell
Get-NetTCPConnection -LocalPort 8089,8090,8091,9000,3306,6379 -State Listen
```

如果端口被非本项目进程占用，通过 `taskkill /PID <pid> /F` 释放。

### 8.4 强制重建数据库表

MySQL 里删除后重建（**会丢数据**）：

```bash
runtime/mysql/bin/mysql.exe -h 127.0.0.1 -P 3306 -uroot -proot \
  -e "DROP DATABASE IF EXISTS xianyu_auto_reply; CREATE DATABASE xianyu_auto_reply CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 然后重跑 init_database（见坑 B）
```

### 8.5 只重启单个服务

现有 launcher 是全量启停，没有单服务重启。要单独重启某个服务，`taskkill` 掉对应 PID 后再 `START.cmd`（launcher 会检测已跑的服务并只补齐缺失的）。
