# 闲鱼自动回复局域网访问设计

## 目标

在不修改闲鱼应用源码、生产监听地址和绿色版更新器安全限制的前提下，使同一局域网内的设备可以通过以下地址访问管理后台：

```text
http://192.168.1.108:8090
```

同时保留未来通过安全内网穿透访问本机服务的能力。

## 已确认现状

- 应用正常监听 `127.0.0.1:8090`。
- 本机以太网 IPv4 地址为 `192.168.1.108/24`。
- 当前网络配置文件为 `Public`。
- `config/portable.json` 和应用配置均将生产地址设为 `127.0.0.1`。
- 绿色版管理器主动拒绝非 `127.0.0.1` 的生产和候选监听配置。
- 应用有登录页，绝大多数管理接口使用 Bearer 鉴权，但原始 HTTP 不提供传输加密，且仍存在少量非鉴权接口。

## 采用方案

保持应用监听不变，通过 Windows TCP PortProxy 增加一个只绑定本机局域网地址的入口：

```text
192.168.1.108:8090
        ↓
127.0.0.1:8090
```

配套增加 Windows 防火墙入站规则，仅允许来源地址 `192.168.1.0/24` 访问 TCP 8090。

## 不采用的方案

### 应用直接监听 `0.0.0.0`

不采用。该方式会破坏绿色版管理器的回环监听安全约束，并扩大应用暴露面。

### 路由器直接映射公网端口 8090

不采用。管理后台不应以原始 HTTP 直接暴露到互联网。

## 实施步骤

1. 记录现有 PortProxy 和相关防火墙规则，作为回滚依据。
2. 确认 `IP Helper` 服务可用；PortProxy 依赖该服务。
3. 添加 TCP IPv4 转发：

   ```text
   listenaddress=192.168.1.108
   listenport=8090
   connectaddress=127.0.0.1
   connectport=8090
   ```

4. 添加防火墙入站允许规则：

   ```text
   名称：XianyuAutoReply-LAN-8090
   协议：TCP
   本地地址：192.168.1.108
   本地端口：8090
   远程地址：192.168.1.0/24
   配置文件：Any
   操作：Allow
   ```

5. 不修改以下文件：

   ```text
   config\portable.json
   releases\<active>\app\global_config.yml
   ```

6. 不重启闲鱼自动回复服务，除非 PortProxy 建立过程中发现端口冲突。

## 验证标准

### 本机验证

- `127.0.0.1:8090` 继续返回管理后台登录页。
- `192.168.1.108:8090` 返回相同登录页。
- 原有 Python 服务继续由原 PID 监听 `127.0.0.1:8090`。
- PortProxy 规则正确指向 `127.0.0.1:8090`。
- 防火墙规则只允许 `192.168.1.0/24`，不是任意远程地址。
- 自动回复 WebSocket 心跳继续正常。

### 局域网设备验证

同一路由器下的其他设备打开：

```text
http://192.168.1.108:8090
```

应看到闲鱼管理系统登录页，并能够使用现有管理账号登录。

## IP 地址稳定性

PortProxy 绑定到 `192.168.1.108`。如果路由器以后为本机分配了不同地址，该入口会失效。

建议在路由器 DHCP 设置中，把本机网卡 MAC 地址固定分配为：

```text
192.168.1.108
```

在完成 DHCP 保留前，每次局域网访问异常都应先检查本机 IPv4 地址是否变化。

## 未来内网穿透设计

未来使用 FRP、Cloudflare Tunnel、Tailscale Serve 或其他穿透方案时，穿透客户端应在本机连接：

```text
http://127.0.0.1:8090
```

公网入口必须满足：

1. 使用 HTTPS；
2. 保留应用自身登录；
3. 最好再增加穿透平台身份验证或访问策略；
4. 不在路由器上直接转发公网 TCP 8090；
5. 不把 Cookie、Token 或登录信息写入公开配置或日志。

未来穿透不需要扩大当前局域网防火墙规则。

## 回滚方案

如果局域网访问配置产生异常：

1. 删除 `192.168.1.108:8090` 对应 PortProxy 规则；
2. 删除防火墙规则 `XianyuAutoReply-LAN-8090`；
3. 确认应用仍监听 `127.0.0.1:8090`；
4. 验证本机管理页面和自动回复不受影响。

回滚不涉及应用数据库、Cookie、订单、卡密或浏览器资料。

## 安全边界

- 当前方案只允许 `192.168.1.0/24` 访问，不允许任意公网来源。
- 局域网内访问仍为 HTTP，登录凭据和会话数据没有 TLS 传输保护，因此只应在可信家庭或办公局域网使用。
- 如果局域网中存在访客或不可信设备，应改用带 HTTPS 和额外访问控制的反向代理或私有 VPN。
